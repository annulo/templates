---
name: 出大纲初稿
description: 给一个选题出文章大纲的初稿：按选题、读者、关键词和选中的产品排好几节，每节写小标题、要点、讲哪个产品，存进选题的写作简报，用户在页面上接着改或在对话里让你改
---

参数：`topic_id` 是选题（topics 表）。用户在「写作简报 → 大纲」点了「AI 出大纲初稿」。只出大纲，**不写正文**。

## 1. 拿上下文

```bash
annulo run content.outlineContext --input '{"topic_id":"<topic_id>"}'
```

- `topic`：标题、角度 `angle`、关键词 `keywords`（第一个是主关键词）；来自搜索的还有搜索词和曝光、排名；
- `brief`：读者 `audience`、读者想解决的问题 `buyer_question`、写作语言 `language`、结尾引导 `cta`、缺的资料 `gaps`；`sections` 是现在的大纲（不是空的就是用户写过或上次出过：在它基础上改，保留用户写的节，别整个推翻）；
- `products`：用户为这篇选中的产品，带全部事实（型号、规格、起订量、认证……）；`other_products` 是别的相关产品，**只用来知道有什么**，不往大纲里挂；
- `project`：项目资料；`similar`：网站上和后台已有的同类文章（标题、`url`），大纲要和它们讲的不一样，能互相链接的在要点里写「链到《…》」。

## 2. 出大纲

怎么排（几节、什么结构、要点写多细）照这件任务的写法：用户改过的在 `user/prompts/brief-outline.md`，没改过用模板默认的 `prompts/brief-outline.md`（开任务时会告诉你用哪份；用户在对话里让你改写法，就把改后的完整写法存到 `user/prompts/brief-outline.md`）。写法和下面的规则冲突时，以规则为准。

每节：
- `heading`：小标题，用写作语言（`brief.language`，没写就照项目语言），读者一眼知道这节回答什么；
- `note`：这节要讲的要点，一两句，用界面语言写给用户看（用户要能看懂、好改）；要用的事实写清出处（哪个产品的哪个参数）；
- `product_ids`：这节讲到的产品，只能是 `products` 里的 id。每个选中的产品至少落在一节里；产品讲得自然：放在读者需要它的那一节（选型、对比、规格、案例），不硬塞。

`brief.cta` 是空的，顺手给一句结尾引导（`cta`）。写的过程中发现缺资料（比如要一张对照表、某个认证没有），写进 `gaps`，一条一行。

## 3. 存

```bash
cat > /tmp/outline.json <<'JSON'
{ "topic_id": "<topic_id>", "sections": [{ "heading": "…", "note": "…", "product_ids": ["…"] }], "cta": "<可选>", "gaps": "<可选>" }
JSON
annulo run content.saveOutline --input @/tmp/outline.json
```

存完回复用户：一共几节、每节一句话、哪个产品放在哪一节；有缺的资料提一句。页面上的大纲会自动换成这一版，用户可以直接在页面上改，也可以在这段对话里说。

用户在这段对话里提意见（少一节、换个顺序、某个产品往前放），改完**整份大纲重新存一次**（覆盖），再说改了哪里。

## 规则

- 只出大纲，不写正文，不改选题标题、关键词和选中的产品；
- 不编事实：参数、认证、案例只用 `products` 和项目资料里有的，没有的写进 `gaps`；
- 不和 `similar` 里的文章重复：同样的问题已经有一篇讲透了，这篇换角度或者链过去；
- 回复用户用界面语言。
