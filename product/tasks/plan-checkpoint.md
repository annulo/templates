---
name: 增长计划检查点
description: 计划到了第 30 / 60 / 90 天：对着开始时的基线看谷歌数据、询盘和做了的事，写结论；30、60 天排下一阶段每周的事，90 天做总复盘
---

参数：`day`（30 / 60 / 90，可以没有，按计划进度算）。

## 1. 拿数据

```bash
annulo run plan.checkpointContext --input '{"day":30}'
```

输出里：`progress` 每个目标的基线、现在、目标和完成度；`items` 计划项做没做（`auto` 是按数据自动判断的）；`gsc.top_pages` 谷歌展示最多的页面（和上一个 28 天比）、`keywords` 在做的和排上了的词；
`keyword_map` 关键词地图（每个主题的目标页面、走到哪一步：none 没页面 / topic 有选题 / draft 写好没发 / live 已上线 / shown 有展示 / top30 / top10，展示、点击、落在这个页面的询盘）、`backlinks` 外链（在线、丢了几条，按类型）；`leads` 计划开始后的询盘按落地页、来源分；`changes` 改动上线后复查的结论；`growth` 这周的增长机会；`catalog` 下一阶段计划项能用的动作（同起草计划，只能用这里的）。

谷歌数据有 2~3 天延迟、新页面收录要一两周，下结论时考虑进去；数据太少（展示不到几百）就说「还看不出趋势」，不硬下结论。

## 2. 写结论

- `summary`：一段话，和开始时比变了多少（三层分开说：做了多少、谷歌展示和排名、点击和询盘），离目标还差多少；
- `wins`：哪些做法有效（按 `keyword_map` 说哪些主题的页面起来了；具体到页面、主题、来源：「/blog/xxx 展示从 0 到 800」「询盘 3 条里 2 条落在产品页 xxx」）；
- `issues`：哪些没起色、为什么（没收录、词太难、计划项没做）；
- `adjustments`：下一阶段怎么调。

## 3. 排下一阶段（30、60 天）

`items` 排下一阶段每周的事（第 2 阶段第 5~8 周，第 3 阶段第 9~13 周），每周 3~5 件，格式同起草计划。按数据排：排在 4~30 位的词优先补内容、点击率低的页面改标题描述、有效的主题继续写、外链和社媒分发跟上、没做完的重要事项挪进来。
目标明显定高或定低了，可以带 `targets`（只写要改的指标）；阶段重点要改带 `phases`（三个阶段都写上）。

## 4. 90 天：总复盘

`day` 是 90 时不排 `items`：`summary` 写目标逐项达成了多少，`wins` 写最有效的做法（按页面、主题、外链来源），`adjustments` 写下一个 90 天的建议。存完计划就结束了，告诉用户可以在「增长计划」页起草下一个 90 天。

## 5. 存

```bash
cat > /tmp/checkpoint.json <<'JSON'
{ "day": 30, "summary": "…", "wins": ["…"], "issues": ["…"], "adjustments": ["…"], "items": [ { "week": 5, "area": "content", "title": "…", "why": "…", "action": { "kind": "go", "view": "search", "params": { "tab": "keywords" } } } ] }
JSON
annulo run plan.saveCheckpoint --input @/tmp/checkpoint.json
```

存完回复用户：一句话总结、最有效的一两件事、下一阶段第一周做什么。用户接着提意见就改了再存一次（同一个 `day` 会覆盖）。

## 规则

- 数字都从输出里来，不编；
- 用用户的话（「谷歌展示次数」「点击」「询盘」），用界面语言写。
