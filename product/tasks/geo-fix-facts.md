---
name: 修正 AI 说错的地方
description: 用户看了 ChatGPT 对公司或产品的回答，标出了说错的地方：查清这个说法从哪来（本站没写清楚、别家页面过时、还是资料本身没更新），写出修正建议存回检测结果
---

参数：`result_id` 是 geo_results 里这条检测结果。

## 1. 拿上下文

```bash
annulo run geo.factsContext --input '{"result_id":"<id>"}'
```

输出里：`report` 是**用户标出的说错的地方**（哪里不对、实际是什么），这是判断的依据；
`question` 是买家问的问题，`answer` 是 ChatGPT 的完整回答（来源链接在正文里），`urls` 是回答引用的网址；
`facts` 是系统里的公司资料和产品库，**可能过时、产品可能没录全**，只作参考，和 `report` 冲突时以用户说的为准；`site` 是网站的域名和几个页面的内容。

## 2. 查这个说法从哪来

按 `report` 一处一处查，要看就用 `curl` 或 `web_fetch` 打开回答里这句话引用的链接和本站相关页面，不要凭印象：

- **本站没写或写得不清楚**（最常见）：写清楚要在哪个页面补什么、怎么写能让 AI 一眼读到；
- **别家页面的信息过时或错了**（出处不是本站）：写清楚是哪个页面、错在哪，建议用户去更新（自己账号的平台、名录）或联系对方；
- **系统里的资料没更新**（`facts` 和用户说的不一样）：提醒用户到「公司与产品」更新，其他功能（写文章、回询盘）也会用到；
- 查不到出处的，如实说查不到。

不编造用户和页面都没有的事实（价格、认证、数量）；需要用户补的写成「补充 xxx（需要你提供）」。

## 3. 存

用界面语言写成 Markdown，每处一小段：AI 说了什么 → 从哪来 → 怎么改（改哪个页面 / 去哪里）。最后一行写「改完后下周检测会自动复查，也可以在页面上重新检测」。

```bash
cat > /tmp/geo-fix.json <<'JSON'
{ "result_id": "<id>", "note": "…" }
JSON
annulo run geo.saveFix --input @/tmp/geo-fix.json
```

存完回复用户：每处说法从哪来、最该先改的一处。**这一步只写建议，不要去改站点代码**；用户确认后要改页面，再按站点的改法去做。
