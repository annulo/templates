name: 出社媒方案
description: 新建社媒内容的第 2 步：按用户的一句话、选的平台、形式和风格卡，给一条视频（或一组图文）出方案：分镜、封面、为什么这样做、每个账号的标题和正文，social-create.savePlan 存成新的一版。只出方案，不录制、不发布
---

参数：`topic_id` 是这条内容（topics 表，向导的设置在 `brief.social`）。用户在「新建社媒内容」第 1 步点了「让 AI 出方案」。

## 1. 拿上下文

```bash
annulo run social-create.context --input '{"topic_id":"<topic_id>"}'
```

- `request`：用户那句话（要做什么、重点讲什么），**最重要**；`notes` 是补充要求（比如结尾放官网、别用某些词），必须照做；
- `format`：`type` 是 `video` 视频还是 `post` 图文；视频的 `duration` 秒数、`aspect` 画幅、`subtitles` 要不要字幕；图文的 `images` 张数；
- `site`：读到的网站。`screens` 是每一屏：`n` 第几屏、`y` 这一屏顶在页面上的位置（像素，窗口 `viewport` 高）、`heading`、`text`，`path` 是这一屏的截图（**一定要打开看**：有动效、3D、对话框的屏最适合放进视频，空白、过渡中、价格表这类不适合）；`full_text` 是网页全文；
- `accounts`：要发的账号：平台 `type`、定位 `profile`、平台限制 `limits`（标题、正文最多多少字、话题几个，`title` 是 0 表示这个平台不发标题）；
- `playbook`：用户选的风格卡（参考博主的写法：标题公式、开场、结构、语气、`fit`、`avoid`），没选是 null；`reference_url` 是用户贴的参考内容（有就打开看它的写法）；
- `product` / `article`：素材是产品或已有文章时的内容；`project` 是项目资料；
- `plan`：上一版方案（用户让你重新出、或在对话里提意见时在它的基础上改）。

## 2. 出方案

怎么出（节奏、镜头怎么排、字幕和文案的风格）照这件任务的写法：用户改过的在 `user/prompts/social-plan.md`，没改过用模板默认的 `prompts/social-plan.md`（开任务时会告诉你用哪份；用户在对话里让你改写法，就把改后的完整写法存到 `user/prompts/social-plan.md`）。写法、风格卡和下面的规则冲突时，以规则为准。

方案的 JSON：

- `title`：这条内容叫什么（后台列表里认它用，界面语言）；`summary`：一句话说这条内容讲什么；
- 视频：`shots` 分镜，按时间排、首尾相接、总长等于 `format.duration`：
  - `start` / `end`：秒；`screen`：用第几屏；`y_from` / `y_to`：这一镜从页面哪个位置滚到哪（像素，用那一屏的 `y` 加减；不滚就两个一样）。一镜 2~6 秒；
  - `caption`：这一镜的字幕（一句，短，中文 16 字以内；界面语言和账号的语言不一样时用账号的语言）；`note`：这一镜画面上是什么、为什么放这里（写给用户看）；
  - 片头或片尾想要一张纯色的字卡：`"card": { "title": "…", "subtitle": "…" }`（这一镜不显示网页）；
- 图文：`images` 每张图：`screen` 用第几屏的截图当底、`title` 图上的大字（短）、`subtitle` 小字（可选），张数照 `format.images`；
- `cover`：视频封面：`title` 封面大字（两行以内，可以用 `\n` 换行）、`subtitle`、`screen` 用第几屏当底、`ratio`（小红书、抖音用 `3:4`，横屏平台用 `16:9`；只发横屏平台就跟视频一样）；
- `rationale`：为什么这样做，3~5 条，每条一句：挑了哪几屏、为什么这样开头、风格卡的哪条用在了哪、用户的补充要求怎么落实的；
- `copies`：**每个账号一份**：`channel_id`、`title`（平台不发标题的也写一个，后台认这条用）、`body`、`tags`（不带 #）；B 站视频加 `category` 分区；小红书图文可以加 `cover_text`。按账号的定位和平台写，不要一份复制给几个账号。

## 3. 存

```bash
cat > /tmp/social-plan.json <<'JSON'
{ "topic_id": "<topic_id>", "plan": { "title": "…", "summary": "…", "shots": [ … ], "cover": { … }, "rationale": [ … ], "copies": [ … ] } }
JSON
annulo run social-create.savePlan --input @/tmp/social-plan.json
```

返回的 `problems` 不是空的（标题、正文超了，话题太多，少了某个账号的文案），按它改了再存一次（会存成新的一版，没关系）。

存完回复用户：一句话说这条内容怎么拍，几个镜头各讲什么，每个平台的标题；请用户在左边的方案页看分镜和封面，没问题点「确认方案，开始制作」。

用户在这段对话里提意见（换一屏、字幕改短、某个平台的标题再长一点），改完**整份方案重新存一次**（存成新的一版，页面上能切回旧版），再说改了哪里。

## 规则

- 只出方案：不录视频、不出图、不建文章、不发帖子（这些在用户确认后由页面上的「开始制作」做）；
- 不编事实：功能、数字、价格、用户评价只用网站文字、产品资料和项目资料里有的；
- 风格卡只学写法（节奏、句式、结构），不搬它的内容和事实；
- 平台限制（`limits`）必须守；不写站外引流（加微信、私信领取）、不用「最好」「第一」「100%」这类绝对化用语；
- 字幕、文案用账号的语言；回复用户用界面语言。
