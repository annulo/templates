---
name: 问助手：关于一条 AI 回答
description: 用户在「AI 搜索推荐」里看了某个 AI（ChatGPT、DeepSeek、豆包…）对一个问题的回答，就这条回答问你：为什么没引用我们、怎么让它推荐我们、这里说错了、这个说法从哪来……查清楚、回答他，结论存回这条回答下面
---

参数：`result_id` 是 geo_results 里这条回答，`ask` 是**用户的原话**（他想知道什么、想做什么）。

## 1. 拿上下文

```bash
annulo run geo.askContext --input '{"result_id":"<id>"}'
```

输出里：
- `engine` 是哪个 AI，`question` 是买家问的问题，`kind` 是 `facts`（品牌问题：AI 怎么介绍这家公司）或 `recommend`（推荐类：买家还不知道这家公司时 AI 推荐了谁）；
- `answer` 是这家 AI 的完整回答，`urls` 是回答引用的网址，`searches` 是它这次搜了什么、搜到哪些网页（有的 AI 拿不到搜索词）；`cited` 是引用了本站，`mentioned` 是提到了但没给链接；
- `others` 是同一个问题**别的 AI** 最近怎么答的、引用了谁（对比用）；
- `report` 是用户之前标过的说错的地方（有的话）；
- `facts` 是系统里的公司资料和产品库，**可能过时、产品可能没录全**，只作参考，和用户说的冲突时以用户为准；`site` 是网站的域名和几个页面的内容。

## 2. 按用户问的去查

先看 `ask` 想要什么，只回答他问的，不要把下面几种都做一遍：

- **为什么没引用 / 没推荐我们**：看这家 AI 搜了什么词、搜到了哪些网页（`searches`），本站有没有出现在里面：
  没出现 → 多半是本站没有回答这个问题的页面，或者排名、收录不够（和谷歌一样）；出现了但没引用 → 对比它引用的页面，本站页面缺什么（直接的回答、数据、规格、对比、案例、结构化的问答）。
  拿 `others` 对比：别家引用了本站，这家没有，说明内容有了、这家没搜到或不偏好这类来源。
- **怎么让它推荐 / 怎么优化**：落到具体的页面和内容：补哪个页面、写什么样的文章（标题、要正面回答的问题）、在哪些第三方网站（名录、评测、问答社区）出现。能写成选题的，告诉用户可以在页面上「写成选题」。
- **说错了 / 这个说法从哪来**：一处一处查，用 `curl` 或 `web_fetch` 打开回答里这句话引用的链接和本站相关页面，不要凭印象：
  本站没写或写得不清楚（最常见）→ 写清楚补哪个页面、怎么写能让 AI 一眼读到；别家页面过时或错了 → 是哪个页面、错在哪，建议去更新或联系对方；系统里的资料没更新 → 提醒用户到「公司与产品」更新；查不到出处的，如实说。
- 别的问题：照着问，查得到的给证据，查不到的说查不到。

不编造用户和页面都没有的事实（价格、认证、数量）；需要用户补的写成「补充 xxx（需要你提供）」。

## 3. 存，再回复

把结论用界面语言写成 Markdown，简短、能照着做：用户问了什么 → 查到的原因（带证据：哪个网址、哪句话）→ 怎么做（改哪个页面 / 写什么 / 去哪里）。存回这条回答，页面上显示在它下面：

```bash
cat > /tmp/geo-ask.json <<'JSON'
{ "result_id": "<id>", "note": "…" }
JSON
annulo run geo.saveFix --input @/tmp/geo-ask.json
```

存完在对话里回复用户，最该先做的一件事放最前面。**这一步只查和写建议，不要去改站点代码、不要自己加问题或改检测设置**；用户确认后要改页面、写文章，再按对应的做法去做。
