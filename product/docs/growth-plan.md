# 90 天增长计划（plan 模块）

外贸和产品运营共用（`targets.json` 里启用 `plan`）。改这块之前先读这篇；改了设计就同步改这里。

## 为什么要有

模板的功能很全（关键词、竞品、网站检查、谷歌排名 + 效果追踪、GA4、内容衰减、AI 搜索、询盘、社媒、增长机会、周报、看板），但没有把它们串起来的东西（2026-11-13 用户反馈）：
- **没有目标**：不知道 90 天要做到什么，也没法说做成了没有；
- **没有规划**：起步六项 + 零散的「今天要做的」+ 每周一张增长机会清单，没有「第几周该做什么、为什么」；
- **功能不联动**：关键词挖出来不知道落到哪个页面，询盘进来不知道是哪个词、哪个页面带来的；
- **没有检验**：效果追踪只看单个改动，没有「和开始时比，第 30 / 60 / 90 天变了多少」。

## 流程

```
AI 起草（任务 draft-plan）：判断从哪个阶段开始、三档目标、三个阶段的重点、开始阶段每周的事 → draft
  → 用户选一档目标，「开始执行」（plan.activate）：记基线、算第 1 天 → active
  → 每周的事：去对应页面做 / 交给助手；能按数据判断的自动标做完
  → Day 30 / 60 检查点（任务 plan-checkpoint）：和基线比、写结论、排下一阶段每周的事、可以调目标
  → Day 90 总复盘 → done → 起草下一个 90 天（draft-plan 读上一份的检查点）
```

阶段：Day 1–30 打地基（关键词布局、竞品分析、修网站、核心页面、外链起步）、Day 31–60 放量优化（快赢词补内容、改标题描述、继续写主题、社媒分发带链接）、Day 61–90 转化（落地页和询盘入口、刷新掉量页面、询盘来源）。

## 定下来的（2026-11-13）

1. **目标先让 AI 给建议，用户选**：AI 给保守 / 正常 / 激进三档（每档每个指标 90 天后要到的数），推荐一档，用户在页面上选；不替用户选（任务里不调 `plan.activate`）。
2. **外链先简单来**：第 1 阶段的计划项里写外链起步（社媒主页填网站链接、每篇文章发社媒带链接、B2B 平台和目录的公司介绍写上网站），还没有单独的外链表；以后再做「外链清单 + 登记 + 检查还在不在」。
3. **老项目要判断从哪个阶段开始**：`judgeStage` 按规则给建议（谷歌数据满 28 天、发了 8 篇以上、有展示 → 第 2 阶段；再加上 15 篇以上、近 28 天点击 ≥ 30 或 5 个词进前 30 → 第 3 阶段），助手看 `facts` 再判断，不一样时写理由。
   从第 2 阶段开始的，第 1 天往前推 30 天（`start_date`），Day 30 检查点不做。
4. **产品运营也上**：模块在 core，两个模板都启用；没开询盘、竞品的模板不出这几个指标和动作（`hasFn` 按文件在不在判断）。

## 指标（`plan.ts` 的 `METRICS`）

分三层，新站 90 天里询盘常常还少，只看询盘的话第 30 天就会觉得没用：

| 层 | 指标 |
|---|---|
| 做了多少 `process` | `pages_published` 网站上发了的文章、`social_published`、`keywords_targeting`、`competitors_watched`、`issues_high_open`（越少越好） |
| 先行 `leading` | `pages_with_impressions`、`impressions_28d`、`keywords_top30`、`keywords_top10`、`geo_visibility` |
| 结果 `result` | `clicks_28d`、`leads_28d`、`deals_open` |

全从业务表算，不调模型、不联网（手机上也能看）；拿不到的是 `null`（没连谷歌、没做过 AI 搜索检测），不当 0。谷歌的 28 天从有数据的最后一天往前数（GSC 有 2~3 天延迟）。
基线是 `activate` 那一刻的 `compute`，存在 `growth_plans.baseline`；进度 = (现在 − 基线) / (目标 − 基线)。

## 计划项（`plan_items`）

一条一个现有功能的动作：`{kind: 'go', view, params}` 或 `{kind: 'task', task, input}`，只能用 `plan.context` 的 `catalog`（`saveDraft` / `saveCheckpoint` 校验）。
能按数据判断的带 `check: { metric, gte, delta? }`（`delta` 是比基线多了多少），`plan.get` 算出来满足就显示「已达成」，不写表；判断不了的用户手动标做完 / 不做。
起草时只排开始阶段的几周（第 1 阶段第 1~4 周、第 2 阶段第 5~8 周、第 3 阶段第 9~13 周），后面的到检查点按数据排：检查点会删掉下一阶段还没做的旧计划项，换成新的。

## 页面和联动

- 侧栏「增长计划」（`view=plan`，`components/views/Plan.tsx`）：没有计划时说明 + 建议阶段 + 起草按钮；草稿时选一档目标；执行中是进度条（第几天 / 90，三个检查点）、到期的检查点、三层目标进度、阶段、检查点结论、每周的事。
- 总览上一张卡片（`PlanCard`）：第几天、关键目标、这周还剩几件事、检查点到了。
- `today.list`（business 模块）把检查点和这周没做完的计划项排在「今天要做的」最前面：用户问「接下来做什么」时助手照它答。
- 起草和检查点都存 `ctx.chat_id`，页面上「继续对话」回到那段对话改。
- 测试：`publish/tests/plan.test.mjs`。

## 关键词地图（增长计划 → 关键词地图，`plan.keywordMap`）

不新建表，按主题现算：关键词表里筛过、没放弃的词按 `cluster` 分，一个主题一个目标页面（词的 `target_page` → 选题写成的文章发布后的网址 → 词的 `gsc_page`）。
阶段 `none` 没页面 → `topic` 有选题 → `draft` 写好没发 → `live` 已上线 → `shown` 谷歌有展示 → `top30` → `top10`。
**阶段只看主题里的词自己的排名**（`gsc_position`、`serp_position`）：页面的平均排名是所有搜索词混在一起的（pofung 的产品页只有几次展示、平均排第 7，排的不是主题词），只作参考显示成「页面平均」。
展示、点击优先用目标页面在 `search_pages` 的数，没有再加词的；询盘按 `leads.landing_page` 和目标页面同一路径算，计划开始后的。每一行按阶段给下一步（去哪个页面）。
指标 `clusters_live`（走到 live 及以后的主题数）可以当计划项的自动判断。

## 外链（增长计划 → 外链，`local/backlinks.ts`，表 `backlinks`）

先简单做：
- 手动登记（同一地址一次），类型：社媒、B2B 平台、行业目录、文章报道、论坛问答、其它；
- `backlinks.sync`：社媒帖子发出去了、正文里有本站链接（带不带 https:// 都认）的，自动登记成 nofollow 的社媒外链；
- `backlinks.check`（每 7 天，`schedules/backlinks.check.json`）：读来源页面找指向本站的 `<a>`，找到是在线（顺便看 rel 是不是 nofollow / ugc / sponsored），404 或找不到是丢了；社媒要登录读不到，不改原来的结论；
- 询盘按 `referrer` 的域名、`utm_source` 和平台名对上外链，算带来了几条。
说清预期：社媒的链接基本是 nofollow，对排名直接帮助有限，价值是品牌、引流、让谷歌更快发现新页面；真正提排名的是行业目录、B2B 平台、行业网站和媒体。GSC 的链接报告没有 API，效果看询盘的来源。
指标 `backlinks_live`。

## 每周总结

`reports.data` 有进行中（或刚结束）的计划时带 `plan`：第几天、阶段、目标进度、这一期该做的计划项做没做、关键词地图各阶段的主题数、外链、到没到检查点、上一次检查点。外贸和产品运营的周报任务里写了先写一段「计划进度」，下周建议优先从计划项里来。
