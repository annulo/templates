# 新建社媒内容（三步向导）

外贸和产品运营的「自媒体内容」页上的「新建社媒内容」：从一个网址做出一条视频（或一组图文），每个平台一个版本，先给方案和设计图、确认了再做。2026-11-17 定的设计：原来五步（素材 → 平台与形式 → 风格 → 方案 → 制作）嫌多，平台、形式、风格大多能按用户那句话自动配好，收进第 1 步。

## 三步

1. **要做什么**：左边填网址（「读网站」用本机 Chrome 一屏一张截图，点一下某屏就不放进内容）、可选关联产品、一句话说要做什么（常用说法点一下填进去）；
   右边「AI 按你这句话配好了」：平台、形式、风格、补充要求各一行，写了为什么这样配，要改就点。底下「让 AI 出方案」。
2. **方案**：AI 出的分镜设计图（每镜的时间、网站真实截图、字幕）或图文的每张图、封面、为什么这样做、每个账号的标题正文。
   要改在对话里说（「继续对话」回到出方案的那段对话），每存一次是新的一版，能切回旧版。「确认方案，开始制作」进第 3 步。
3. **成片与发布**：「开始制作」录网站、合成视频、出封面（图文是出图），建一篇文章挂上成片，再给每个账号存一条待审帖子；「去审核发布」打开这篇文章，照原来的发布流程审、改、发。

方案没确认前不录制、不发。

## 自动配（确定的规则，`components/SocialCreate.tsx` 的 `parseRequest` / `suggest`，不调模型）

- 那句话里认平台名（小红书、抖音、B 站、X、领英…）、时长（30 秒、1 分钟）、画幅（4:3、竖屏、横屏、方形）、形式（视频 / 图文、几张图）；
- 平台：用户说到的、已连账号的选上（标「你说的」），再按形式和画幅推荐一个（横屏推 B 站、YouTube、X、LinkedIn…，竖屏推抖音、小红书、Instagram，标「推荐」写原因）；什么都没说就按横屏推荐最多 3 个；说了但没连的平台提示去连；
- 画幅：说了用说的；没说的看平台，全是竖屏平台用 9:16（图文 3:4），否则 16:9；横屏视频发竖屏平台提示「会有留白，封面另出 3:4」；
- 风格：灵感库的风格卡里，平台对得上、类型对得上、用得多的排前面，选第一张；没有卡就「不照谁，按账号定位写」。也能贴一个参考链接；
- 用户手动改过哪一项（`touched.platforms / format / style`），之后改那句话也不再动它。

## 数据

一条社媒内容就是一个选题（`topics`，`workspace=social`），向导的状态都在 `brief.social`：
`source`（网址、关联产品）、`site`（读到的网站：标题、每屏的截图路径 `file`、位置 `y`、标题和文字）、`skip`（不放进内容的屏）、`request`、`platforms`（`channel_id`、`type`、`why`）、`format`（`type`、`duration`、`aspect`、`subtitles`、`images`）、
`style` / `playbook_id` / `reference_url`、`notes`、`plan`（当前方案）和 `plans`（最近 8 版）、`produced`（文章 id、成片、封面、各账号帖子的结果）、`folder`（工作文件夹）。
`content.saveBrief` 存简报时原样留着 `social`。选题上照常有 `title`、`content_type`、`target_platform`、`playbook_id`，内容列表、归属、出处都不用改。

向导做的选题在列表里点开进向导（`?create=<选题 id>`），新建是 `?create=new`。

## 本机函数和任务

- `local/social-create.ts`：`save`（页面自动存）、`readSite`、`context`（出方案取数）、`savePlan`（存一版方案，返回平台限制上的问题）、`pickPlan`、`produce`；
- `tasks/social-plan.md`：出方案，写法 `prompts/social-plan.md`（用户能在「AI 要求」里改，存到 `user/prompts/social-plan.md`）。只出方案，不录制、不发；
- 制作是确定的操作，不经过助手：`produce` 是本机函数（按钮 `RunButton`，有进度）。

## 录网站：`scripts/social-video.mjs`

Annulo 的 `ctx.browser` 截图只给一个只能拿去上传的句柄，存不成文件，所以录制不走它：本机函数用 `ctx.exec('node', …)` 跑项目里的这个脚本，
它起一个无界面的 Chrome（临时目录，不碰用户的登录态），走调试协议（CDP，Node 22 自带 WebSocket，不装 npm 包）：

- `screens`：1440×1080 打开网址，先滚一遍触发懒加载和动效，一屏一张 jpg（最多 10 屏），记下每屏的位置、标题和文字；
- `record`：按分镜一帧一帧滚到该在的位置（镜内缓动滚动、镜间硬切），字幕和片头片尾字卡画在网页上（用系统字体，中文不用另找字体文件），截图后 ffmpeg 合成 H.264；30 秒的片子大概 1~2 分钟；
- `cover`：滚到某屏，叠渐变和大字，出 png（封面、图文的每张图）。

画幅 → 窗口：4:3 1440×1080、16:9 1440×810、1:1 1080×1080、3:4 810×1080（×4/3）、9:16 用手机版网页 405×720（×8/3，分镜位置按页面高度换算）。
要用户电脑上有 Chrome（或 Edge、Chromium，`ANNULO_CHROME` 指定）、Node 22+、ffmpeg；没有就报错说怎么装。只能在本机版用（工作目录在对象存储上的服务端部署不行）。

成片、封面、截图放在工作目录的 `社媒内容/<日期>-<域名>-<id>/`，文件名带方案版本（`video-v2.mp4`）；用 `ctx.fs.toLocal` 存成本机文件交给 `assets.add`（视频 `use: true`、封面 `use: 'cover'`）。

## 帖子

每个账号一条待审帖子：`produce` 直接调社媒插件该平台的 `save`（`plugins/social/local/_platforms.ts`），和写作任务存的一样，视频带 `video`、`video_cover`；这个账号已经有没发出去的那一版就改它。
平台规格的问题（字数、话题）`savePlan` 时就按插件的 `fieldsFor` 查出来让 AI 改，`save` 返回的 `problems` 也显示在第 3 步。
