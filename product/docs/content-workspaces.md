# 网站与自媒体内容工作区

网站运营包含网站内容、SEO 规划、搜索表现、GEO、网站检查、访问与效果复盘。自媒体运营包含内容管理（带每条内容的数据和复盘）、灵感库、发布日历、账号与数据。产品事实、用户场景、素材与任务总览共用。运营主题保留原记录与旧链接，作为内容的关联信息使用。

## 同一条内容流程

各自的内容管理将 marketing_plans、topics 与 articles 按已有 ID 关联：计划→选题→成品显示为一行。不同标题不作为身份，同名记录不会合并；额外版本和复制的草稿仍有独立入口。计划详情、选题简报、正文编辑、改写、复制与原发布记录均复用已有功能。

状态从本工作区的真实记录计算：待创作、制作中、草稿、待发布、已排期、已发布、待核对、有卡点与归档。历史发布声明、选题完成和制作完成均不能代替真实发布结果。同一原文用于网站和社媒时，保留两边的入口和全部历史回执，状态按当前工作区判断。

所有状态的任务都可再次编辑，包括已发布、已排期和已归档。点击列表或计划详情中的状态标签，可选择任意任务进度，也可恢复自动判断。`content-workspace.setStage` 把当前工作区的进度存入主记录的 `workflow_stages` JSON（优先计划，其次正文、选题），保留另一工作区的进度，不修改正文、素材、选题创作状态或发布回执。手动进度优先用于列表、详情与状态筛选；恢复自动判断后重新显示实际记录对应的进度。手动设置已发布或已排期只更改任务状态，不执行发布、取消排期、生成发布回执或创建复盘记录。

### 状态与发布链接：每种状态一样看、一样改

不管内容走到哪一步（只有选题、有计划、有草稿、已发布），看和改都是同一套：

- **列表每一行**：标题点了进这条走得最远的记录（有成品进正文，没有成品进计划，只有选题进选题）；类型、目标、发布链接（站点名小块，点了打开）在标题下面一行；右边固定是状态标签和「⋯」菜单，菜单里有计划信息、编辑选题（有就显示），有成品的再加改写、复制、删除。
- **三种详情**（正文页、计划详情、选题弹窗）顶上都是状态标签，下面都有同一个「发布链接」块。正文页上面已经列了发布记录，这里只列手动关联的链接。
- **改的地方只有一个弹窗「状态与发布链接」**：状态标签和发布链接块的「编辑链接 / 添加链接」都打开它。上面选状态（任意状态或自动判断），下面是发布链接：发布记录、已核对回执里的链接只读带出（标「发布记录」）；手动关联的链接每条一个输入框，可以改、可以删、可以加，最多 20 条。网站和自媒体都能关联；自媒体标为「已发布」又没有任何链接时不能保存。

`content-workspace.setStage` 的 `links` 是当前工作区手动关联链接的完整列表，和状态在同一次调用里保存，写到主记录（优先计划，其次正文、选题）的 `publication_links.<工作区>`；同一条流程里选题、草稿上以前存的这个工作区的链接一起挪到主记录，删掉的不会从别的记录里冒回来，另一个工作区的链接不动。仅接受不含登录凭据的绝对 HTTP/HTTPS 地址。老的 `published_url`（只能追加、只用于自媒体已发布）继续能用。

手动关联的链接是用户确认的记录，不伪造 `social_posts`、平台帖子 ID、互动指标或发布时间；需要自动复盘时，仍走账号、链接、时间齐全的核对回执流程。改状态或恢复自动判断不删链接，恢复自动判断时手动关联的链接可证明已发布。

## 社媒内容的数据挂在内容上

自媒体的内容和数据不分两处看：单篇的数据跟着内容走，账号页只放账号层面的东西。

- **列表每一行带数据**：已发布的内容汇总它在各账号帖子（`social_posts`）的浏览、点赞、评论，再加近 7 天浏览涨了多少（`content-workspace.context` 的 `post_gains`，口径和社媒插件 `social/stats` 一样：最新一天 − 期初前最后一天，期初前没记录、又是这 7 天发的从 0 算，否则不显示）。可以按「浏览最多」「近 7 天涨得最多」排。
- **帖子怎么算进一条内容**：帖子的 `article_id` 是这条内容的正文；或者帖子在平台上的 id（`post_id`）是这条内容确认过的发布链接（手动关联的链接、核对过的回执）路径里的一段——用户确认过的链接，不按标题猜。
- **在平台上直接发的帖子**（没有 `article_id`、也没被链接对上）单独一栏「在平台上发的」，不混进本工作区的列表（常有几百条）。点「并入内容」：关联到已有内容，或存为一条内容（`content-workspace.adoptPost`，只写帖子的 `article_id`，存为内容时用帖子的标题、正文、配图建一条 `post` / `video` 类型的内容；帖子本身和它的数据不改）。
- **复盘**是自媒体内容里的「待复盘」一栏（`GrowthReviews`），工作台的待复盘入口打开它。
- **内容详情里的「发布后的效果」**（`components/ContentPerformance.tsx`，正文页的发布记录下面、计划详情的发布链接下面）：合计一行；每个平台版本一张小图，各用自己的刻度（平台之间的量级差得多，画在一张图上小的会被压平），可切浏览、点赞、收藏、评论，数据是 `content-workspace.performance` 从 `social_post_daily` 取的每天累计值，不到两天的记录只给提示；下面是这条内容（按计划、正文的 id）的复盘，在这里就能记录。
- **出选题参考数据**：`topics.context` 在自媒体工作区带 `performance`（`content-workspace.ranking`）：近 180 天发的内容按平台分开排，`top` 浏览最多、`rising` 近 7 天涨得最快、`low` 发出去一周以上浏览最少，每条有标题、切入点或正文摘要、互动率。`tasks/suggest-topics.md` 让 AI 延续做得好的主题和形式、少出和差的一样的，在切入点里写依据，数字照抄不编。
- **侧栏**：自媒体运营是「自媒体内容 · 灵感库 · 发布日历 · 账号与数据」。账号与数据分「账号」（连接、发布状态、定位、账号内容策略）和「数据表现」（账号的粉丝和互动）。老的 `view=social-metrics` 链接打开账号的数据表现。

## 归属与兼容

归属依据明确的 workspace、目标平台/账号、引用的网站、保存的选题渠道以及实际发布记录。不能用长文、笔记、视频格式或标题猜测归属。来源为搜索或 GEO 的选题属于网站；归属信息不足的旧记录显示在「待确认归属」。

页面读取不自动改写或迁移数据。用户确认归属时，content-workspace.assign 只在同一流程的原记录上保存 workspace 元数据，不复制、删除内容，不改变状态、素材、参考快照或发布记录；重复确认幂等。已有不同目标的内容不允许通过这个入口移走。

新建选题、自己写内容、AI 创作和灵感生成选题均延续当前工作区。网站创作使用网站上下文；自媒体长文按账号表达，不默认读取网站样稿。发布弹窗仅提供当前工作区的网站或社媒账号；正文详情仍显示所有历史发布记录。

旧 view=content 的 article、topic、plan 链接继续打开原记录，旧灵感链接进入灵感库。所有旧表和 ID 保持兼容，首次整理无需批量数据迁移。自媒体日历展示原 social_posts，网站与社媒的复盘队列分别展示。
