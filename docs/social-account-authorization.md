# 社媒授权集中在项目的账号页

2026-11-26 流程简化：平台只在添加入口选一次，授权弹窗不再显示三平台切换。官方授权成功后，严格按当前项目保存的添加意图和返回账号自动绑定本次授权内的可用账号／公共主页，关闭弹窗并刷新账号列表；管理重连只更新原目标。浏览器锁防止重复回调，成功通知发起窗口刷新；失败保留显式重试，刷新不重复执行失败操作，已有记录复用，关闭添加流程后不再绑定。使用已有授权和管理连接仍可选择账号／素材库。以下统一弹窗章节的再次确认步骤由本节取代。

2026-11-26 统一弹窗：按用户选择的居中弹窗方案，三个平台共用 `SocialAuthorizationDialog` / `SocialAuthorizationFlow`。统一「官方授权 → 确认账号 → 完成」，只在用户点击「添加到项目／保存连接设置」时写账号；授权返回、刷新及平台切换都不自动绑定。单一资产预选，多资产选择；Facebook 支持多选公共主页。管理入口统一徽标、授权到期与权限提示、检测、重连和确认断开；Instagram／Threads 的素材库在相同的可选折叠区。返回指定来源失踪时不兜底到其他授权。旧来源与个人主页保留，不自动迁移。下文 11-25 的自动绑定行为由本节取代。

2026-11-26 上线界面：Instagram 和 Threads 仅显示官方授权，移除粘贴口令、开发者后台取口令及 Instagram 浏览器登录入口，连接不可用时提示并允许刷新，不回退到手动模式。删除内测标签与帮助中的内测说明，但不改变服务端权限或开放资格。旧记录及发布历史保留：Threads 可明确授权同一账号切换；Instagram 旧来源不被覆盖，通过官方授权添加独立连接。

2026-11-26：产品运营模板的 `lib/edition.ts` 平台列表补上 Facebook，「网站和账号」与「社媒账号」的添加弹窗复用已有官方授权、公共主页选择及项目绑定流程。

2026-11-25：用户要求每个项目各自连接社媒账号，日常操作统一放在模板「网站和账号／账号」，不再要求先到 Annulo 设置授权。

- 添加账号时直接调用 Annulo 已有的项目连接接口；授权回来后选择 Facebook 公共主页、Instagram 资产或 Threads 账号并绑定。已授权账号直接复用，不强制重复登录。
- 新 Facebook、Instagram 账号优先显示官方授权；已有浏览器、手动口令账号保留原连接方式，不自动迁移历史数据。可用性及权限继续由连接服务和 Meta 控制。
- 管理连接时查看到期、权限缺失及续期失败，重新授权或确认断开。断开会影响当前项目内所有依赖该授权的账号，保留账号及历史；不影响其他项目。平台自身的全局撤权仍在平台账号安全页操作。
- Threads 有多个授权时明确选择账号并把 account 传给插件，不靠默认账号猜测。
- OAuth 回调、凭据保存、项目隔离和自动续期仍由 Annulo 的可信连接层承担；模板页面只拿连接标识与状态。Instagram 凭据仍由连接服务保管，不复制进模板文件或业务表。

2026-11-25 修正授权返回衔接（源码，待配套 API 68 客户端发布）：连接开始带 `return_to` 项目内路径。可信回调保存发起项目，回跳附本次实际账号标识与结果，不将项目页面地址发给 broker。模板以项目源存储的短期随机意图恢复添加界面，单一可用 IG 资产或 Threads 账号继续绑定，Facebook 自动读取主页供用户勾选。多个 IG 资产仍显式选择；失败不假报成功，重复返回不自动重复添加，旧手填口令账号不自动迁移。客户端设置页不再展示三个社媒操作卡片，已有连接 API 保留。

客户端 API 68 以下不能使用此返回契约，三个模板的最低能力版本同步提高。客户端未发布前不能把源码修复视为用户安装版已生效。

验证：creator/product 类型检查；用 `--local` 应用到三平台联调项目检查默认授权入口、已有连接、到期和断开确认。页面验证不执行真实断开或发布操作。
