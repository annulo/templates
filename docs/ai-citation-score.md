# AI 引用分

长文好不好被 AI 读懂、愿不愿意原样引用，对标 TradeMax 的 AEO 评分（外贸客户提的需求，整体规划在外贸仓库的 `templates/trade/docs/aeo-score.md`）。
产品运营和外贸模板都用；自媒体模板没有独立站，不显示。界面上叫「AI 引用分」，不说 AEO。

## 原则

和 `core/features/websites/docs/ai-search.md` 的「只给事实，不给判断」一致：

- **每一项都是从正文 HTML 机械数出来的事实**（第一段多少词、有没有问句小标题、几处带单位的数字、链接指向哪），分数只是加总。不调模型：秒出、每次一样、不花钱。
- 「写得好不好」「独不独特」这种要理解才能判断的，用规则近似（见下表），说明里写清楚是按什么数的。
- 分数总和「扣在哪、怎么改、一个按钮」一起出现。
- 分数说的是「好不好读、好不好引用」，不是「AI 会不会推荐你」（那是 AI 搜索推荐的实测），文案里说清楚，两边不混成一个数。

## 规则（`core/local/_aeo.ts`）

只给长文（`type=article`）算。中文按字数、英文按词数（中日韩字符超过三成算中文）。

**整篇 10 项**，各占 10%：标题长度、摘要 20–160 字、开头先答（第一段 60–220 字 / 30–90 词）、正文够长（1200 字 / 600 词）、至少 3 个 H2/H3、至少一个问句小标题、有列表或表格、至少 5 处数据（数字带单位、认证、型号）、至少一条外部链接、至少一条内链（相对地址或公司资料 `website_url` 的域名）。

**段落 5 维**（每个段落、列表、表格算一块，各 20 分；不到 15 字 / 8 词的段落不算）：

| 维度 | 规则 |
|---|---|
| 长度合适 | 段落 60–250 字 / 30–120 词；列表、表格至少 3 项 |
| 单独能看懂 | 不以「这、它、此外、上述 / This、It、However…」开头 |
| 结构清楚 | 小标题下的头两段（问句小标题下都算），或者是列表 / 表格 |
| 有数据 | 有数字带单位、认证（CE、ISO 9001…）或型号 |
| 具体不空泛 | 没有套话（高品质、行业领先、high quality、leading manufacturer…），并点名了具体的东西：数据、公司资料和产品目录里的品牌词 / 产品名 / 型号、专有名词 |

总分 = 段落分（开头三块权重加倍）× 0.6 + 整篇 × 0.4。A ≥ 90、B ≥ 75、C ≥ 60、D ≥ 40，其余 F。最弱的三块（低于 80）点名。

阈值拿本机 7 篇真实长文校准过（2026-10-23）：第一版「结构」只认问句小标题、「具体」必须有数据，全是 D；放宽后在 C、D 之间，扣分落在没数字、没内链、摘要超长上，和读下来的感觉一致。改规则时先跑 `publish/tests/aeo.test.mjs`，再拿真实文章看分布。

## 放在哪

- **不存表，显示时现算**：文章页保存是直接写表、AI 改文章走 `content.update`、`work-on-article` 又是一条路，存起来要在每条路上补；现算只要一份纯函数，正文一变分数就跟着变（编辑时按编辑框的内容算）。
- **文章页**（`core/components/AiScore.tsx`，`ArticleDetail` 正文下面）：等级和分数，点开看没过的项、最弱的几段、「交给 AI 改这几处」。按钮把扣分项写成说明，交给「在这篇上做」（有的模板）或「AI 修改」。
- **网站文章列表**：每行一个等级（产品运营、外贸各自的列表加的 `AiScoreTag`）。
- **发布弹窗**：勾了网站时显示分数；D、F 级多提醒一句，**不拦发布**。
- 只在项目里有独立站（`isSite`）、而且不是社媒工作区时显示。
- **助手**：`aeo.article({ article_id })` 返回分数、没过的项和最弱的段落；写文章、改文章、在这篇上做的任务存完长文跑它（写文章是 C 级及以下改一轮），回复里带一句分数。品牌词、型号、域名从 `profile`、`products` 读，没有这两张表的模板当空的。
- **写法**：两个模板的 `prompts/write-article.md` 长文一节写进了这些规则，照写分数自然高，评分是兜底。
