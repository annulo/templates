# 内容模型：内容、产物、发布

2026-10-15 讨论中，**还没定、还没动代码**。几个模板（自媒体、产品运营、外贸）共用的内容中心都受影响。上一步的设计（稿子、产物、交给 AI、引用）见同目录的 `artifacts.md`，本稿在它之上改「文章」这一层。

## 遇到的真实问题

### 一篇里做了两支片子，发不出去

在「测试自媒体」里重做 Annulo 宣传片：一篇视频文章，稿子里写了要重做什么、参考旧版 v1 的片子（挂在这篇的产物里）。和助手聊下来，要做两支：A 外贸版、B 开源版。

助手停下来让用户选：「拆成两篇，还是都记在这一篇的稿子里？」。用户说「就一篇」，再问「但是一篇没办法发布两个社交媒体对吧？」。助手确认：一篇文章发出去的永远是同一份（同一个标题、同一段简介、标着「正在使用」的那个视频），要两支都发，只能：

- **硬用一篇**：先发 A，再把发布用的视频换成 B 发第二次；两支的标题、简介没法分开写，发布记录和数据也混在一篇里；
- **到发布时再拆**：A、B 都在这篇里做，要发时为 B 另建一篇。

两种都别扭。我们接着想的补丁（产物上「另建一篇来发」、两篇之间显示「来自 / 拆出」）也别扭：它们都在给模型打补丁，用户还得先理解「一篇只能发一份」这条规矩。

### 没有 Annulo 时，同样的事一点都不别扭

用户原来的做法：Notion 写文档 → 让 AI 优化 → 建一个 git 仓库 → AI 生成脚本、用户反复改 → 生成视频；想留的让 AI 存成文件，A、B 两个版本的视频和文案（md）都在仓库里 → 发布时打开平台，粘贴文案、传视频，发两次。

这里**干活的地方**（仓库）和**发出去的东西**（每次发时挑的视频 + 文案）是分开的。仓库里有几个版本都行，发几次、每次发哪份，到发的时候才决定。

### 别的地方已经在绕这个问题

- **改写另存一篇**：图文要发成视频、长文要发成小红书，都是「改写」另存一篇新文章（`source_id` 指回原文，原文下面列「改写出的文章」）。同一件事要发到几种平台，就拆成几篇。
- **产品运营把三条记录拼成一行**：`product/docs/content-workspaces.md` 里，计划（`marketing_plans`）→ 选题（`topics`）→ 成品（`articles`）按 id 关联，在列表里**显示为一行**，状态、发布链接存在「走得最远的那条记录」上，选题、草稿上的链接要挪到主记录。用户心里是一件事，表里是三条，页面只好拼起来。
- **「正在使用」**：产物里要标一个「正在使用」，因为文章只能带一个发布用的视频。它其实只是「发布时默认选哪个」。
- **社媒插件已经是「每次发一份」**：插件的帖子表（`social_posts`）每条都有自己的标题、正文、配图、视频，按账号存，发出去的就是这一条。限制在于一篇文章在一个账号上只能有一条没发出去的帖子（`existing()` 按 `article_id + channel_id` 找），帖子的内容也是从文章字段改写来的。

## 问题出在哪

**「文章」同时是两样东西**：

1. **干活的地方**：对应原来的仓库。稿子、脚本、做出来的各个版本都在这里；
2. **要发出去的那一份**：一个类型（长文 / 图文 / 视频）、一个标题、一段正文、一个视频，发布记录挂在它身上。

两样绑在一起，干活的地方就只能产出一份能发的东西。做出两个版本，模型就要求用户先决定「拆不拆」；同一件事要发到不同形式的平台，就要拆成几篇；一件事从想法走到成品，就散成选题、计划、文章几条记录。

## 新的模型

### 内容

把「文章」改叫**内容**（英文 Content）。**一条内容就是原来的一个仓库：一件事从想法到发出去的全部。**

- 页面上本来就叫「内容中心」「内容详情」，只是按钮和提示里还说「文章」「这篇」，统一成「内容」「这条」。
- 一条内容有：标题、**稿子**（文档、要求、大纲、剧本，可选，见 `artifacts.md`）、**产物**（视频、一组图、文案……）、对话、发布记录。
- **表名 `articles` 和字段都不改**，只改界面的说法和概念。老项目升级不用迁移这一层。

不用「作品」（听起来是成品）、「项目」（Annulo 里一个项目是整个业务）。

### 文案也是产物

- 现在文章的正文（标题、正文或简介、话题）是唯一能发的文字。改成：**文案和视频、图片一样是产物**，一条内容里可以有几份（A 版文案、B 版文案、英文版……），AI 想出几个版本就存几个。
- 内容自己的正文还在，作为「默认的那份文案」：只发一份的快速路径不变（新建、写好、发）。
- 文案产物存什么（纯文字 / 富文本、标题和话题放哪）待定，倾向和资料库的文件一样是一个 md 文件，或者资料库里一条带文字的记录。

### 发布是挑选

- 点「发布」：选账号，再**挑这次发什么**：哪个视频或哪组图、哪份文案。默认是最近的那个视频 / 那组图、内容的正文，所以只发一份时和现在一样点下去就行。
- **类型跟着发布走**：挑了视频就按视频发，挑了文案加一组图就按图文发，只挑了文案就按长文发。内容本身不再必须定一个类型；可以留一个「主要做成什么」，只给列表筛选用。
- 同一条内容可以发很多次：A、B 两支各发一次；同一支发到抖音和 B 站；隔一个月换个标题再发一次。
- 发布记录记下这次用了哪些产物（资料库 id），数据按发布记录看。列表上的状态从「这篇发没发」变成「发了几次、发到了哪」。
- **「正在使用」去掉**，变成发布框里的默认选择。

宣传片的例子在新模型里：一条内容「Annulo 宣传片（重做）」，稿子写要求；助手在同一段对话里做出 A、B 两支视频和两份文案，都是这条内容的产物；要发时点两次「发布」，一次挑 A 的视频和文案，一次挑 B 的。助手不用停下来问拆不拆。

### 改写

- 「改写成小红书笔记」「做成视频」不再另存一篇：就是**在这条内容上做**一个新产物（一组图 + 一份笔记文案、一支视频），预设的两种做法（`artifacts.md`「交给 AI」）只剩「在这条上做」。
- 真要另起一件事（拿这条内容当素材写一条全新的），就是新建一条内容，稿子里引用原来那条（`@articles:<id>`）。不记来源关系，不显示「改写自」。

### 选题

选题表（`topics`）现在存：标题、切入点、关键词、来源（手动、AI、搜索、GEO）、搜索数据、写作简报（`brief`）、状态（想法 / 在写 / 写完 / 放弃）、写成的文章（`article_id`）。它和文章一对一，写完以后选题就只是一条历史。

**选题就是还没开始做的内容**，建议并成一个：

- 「出一批选题」就是新建几条状态为「想法」的内容；选题池是内容列表按「想法」筛出来的那部分。
- 切入点、写作简报就是稿子的开头；关键词、来源、搜索数据作为内容的字段留着。
- 「开始写」不再新建一条文章、把 `article_id` 写回选题：同一条内容往下做就行。
- 「避免重复」的记忆：所有内容（包括放弃的）的标题都在一张表里，查一张表就够。
- 产品运营的「计划 → 选题 → 成品拼成一行」就少了一层：选题和成品本来是同一条。计划（一个营销计划下面有好几条内容）是更上面一层，不在本稿里动。

代价：选题要从 `topics` 搬到 `articles`（状态「想法」），老项目升级时要迁移；用 `topic_id`、`topics.article_id` 的地方（写作任务、GEO 写成选题、搜索选题、产品运营的拼行）都要改。

不并也可以：选题留作一个轻量的池子（一次出十几个、大多会放弃），「开始做」时变成内容、选题标记用掉。代价是用户眼里还是两样东西，产品运营的拼行还在。倾向于并。

## 还没定的

1. 选题并不并进内容（倾向并）。
2. 文案产物存成什么：资料库的一个 md 文件，还是资料库里一条带标题、正文、话题的记录。
3. 内容的类型字段：去掉，还是留作「主要做成什么」只给筛选。
4. 社媒插件：发布框挑好的内容怎么交给插件（现在帖子从文章字段改写来、一篇在一个账号只有一条没发的帖子），要改插件的 `save` / `context`，让一条内容在一个账号上能有好几条帖子，每条记下用了哪些产物。
5. 网站（长文发到自己的站、CMS）这条路怎么挑：长文一般就是内容的正文，可能不用挑。
6. 老数据：已经拆成几篇的改写（`source_id`）留着不动，还是合回一条。

## 落地（定了以后）

- 都在 `core/` 和社媒插件里改：界面说法、发布框挑选、文案产物、发布记录存产物 id、列表状态按发布记录算；选题合并的话加迁移。
- 先在自媒体模板里打磨，再给产品运营、外贸接上；`artifacts.md` 里和本稿冲突的地方（「另写一篇」、「正在使用」、按类型的「用这个」）定了以后一起改。
