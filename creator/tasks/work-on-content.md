---
name: 在这条内容上做
description: 在一条内容的文件夹里照用户的要求做事：照稿子写文案、写脚本、配图、做视频……做出来的都是这条内容文件夹里的文件；用户在这段对话里接着改
---

参数：`article_id` 是这条内容，`note` 是用户这次的要求（来自一条 AI 预设，或者用户自己写的一句）。**照 `note` 做，做什么都由它定**：可能是写一份文案、改文案（「改得口语一点」），写脚本，做一组图、一条视频、一个网页，也可能几样都要、要几个版本。

每条内容一个文件夹（`docs/content-model.md`）：稿子、脚本、文案、视频都是里面的文件，用户在内容页上直接看、直接改。**做出来的东西都放进这个文件夹**，不用 `annulo upload`、`assets.add`，也不用 `content.update` 写正文（用户明确要求的除外）。

## 1. 拿文件夹和上下文

```bash
annulo run folder.create --input '{"article_id":"<article_id>"}'   # → { dir, folder_id, local }：文件夹在哪，没有就建；同时把这段对话记到这条内容上
annulo run work.context --input '{"article_id":"<article_id>"}'
```

**文件夹不在你手边的时候**：你在用户自己的电脑上跑（系统提示里有「你在用户自己的电脑上」），或者 `local` 是 false（工作目录在对象存储里），`dir` 这个路径你直接读写不了，都用 `annulo fs`（`<path>` 是 `folder.create` 返回的 `path`）：

```bash
annulo fs ls "<path>"                          # 先看里面有什么（只列清单，不下载；视频这类大文件别急着拉）
annulo fs get "<path>/稿子.md" /tmp/稿子.md     # 只看、只改一两个文件：取下来，改完 annulo fs put <本机文件> "<path>/稿子.md"
annulo fs pull "<path>" "<本机目录，比如 ~/Annulo-work/这条内容的名字>"   # 要在整个文件夹里干活（做视频、做一组图）：拉下来，之后下面说的 <dir> 都是这个本机目录
cd "<本机目录>" && annulo fs push              # 做完推回去：只推改过的；两边都改了的两份都留，看它的提示；没推上去的文件用户和同事看不到
```

`folder_id` 是空的（老版本 Annulo）就照旧直接用 `dir`。

`work.context` 里用这几样：`article` 的 `type`（主要做成什么：长文 article / 图文 post / 视频 video）、`title`；`platforms`（这种类型在用户各平台的限制：标题、正文、话题、配图张数上限，视频是 `only` 还是 `optional`）；`project`（我的定位：语气、写给谁、不写什么）。它给的 `draft`、`body`、`artifacts` 是老数据，**以文件夹里的文件为准**。

然后看文件夹里有什么（`ls -R "<dir>"`），先读最外层的 **`稿子.md`**（英文界面是 `brief.md`）：这条内容要做什么、要求、大纲、参考，是用户写的。别的文件（脚本、文案、参考资料、上一版的视频）按需要读。

## 2. 做

- **文案**（要发出去的文字）写成名字带「文案」的 `.md`（英文界面 `copy.md`）：开头用 `---` 包住 `title:`、`tags:`（逗号分隔），下面是正文或视频简介。用户点「发布」时挑这次发哪份文案、哪个视频。
  - 写：照用户的写作要求（改过的在 `user/prompts/write-article.md`，没改过用 `prompts/write-article.md`，看这种类型对应的那一节）。
  - 改：以文件现在的内容为准（用户可能刚手动改过），只改要求里提到的部分，照用户改文章的要求（`user/prompts/revise-article.md`，没有就用 `prompts/revise-article.md`）。
  - 字数、话题个数不超过 `platforms` 里最严的那个。不编造稿子和定位里没有的数据、案例、经历。
- **长文**写成 `.md`，图放在旁边的目录里用相对路径引用（`![](图/1.png)`）；视频用 `<video src="视频.mp4" width="1280" height="720" controls></video>`。用户在页面上用富文本编辑器改它。
- **脚本、分镜、提示词**这类用户要看、要改的写成 `.md` 放进文件夹。
- **图片、视频**：用什么做由你定（图片可以用模型生成、用代码画；视频可以用 Remotion、ffmpeg……），`note` 里指定了就用它，缺的工具自己装，装了什么在回复里说。成品放进文件夹；装依赖的工程（Remotion 项目这类）可以放在工作目录里共用的地方（系统提示「工作文件放哪」），几条内容共用一份，成品再放回这条内容的文件夹。
- **几个版本**（A 版、B 版，外贸版、开源版）：每个版本一个目录，里面放这一版的脚本、文案、成片，用户发布时分别挑。
- 尺寸按平台：小红书、抖音竖屏 3:4 / 9:16，YouTube、B 站横屏 16:9；图文的张数不超过 `platforms` 的 `images_max`。画面里的文字只用稿子、文案和定位里有的。做完自己看一遍：图片文字有没有出界、被裁、太小；视频抽几帧看。
- **中间产物不和成品混在一起**：草稿视频、草稿音频（配音的分段、没剪的素材）、试渲染的片段、缓存放进文件夹的 `草稿/`（英文界面 `drafts/`）。文件夹里的 `.annuloignore` 已经写了它：在你电脑上做时这些不会推到服务器、不占团队的空间，页面上也一眼分得清哪些是成品。要留给用户挑的几个版本是成品，放外面。在服务器上直接做、工作目录在对象存储里时，中间产物放系统临时目录，只把成品写进文件夹。
- 文件名用用户看得懂的中文（英文界面用英文），不要用 id、时间戳。
- 做不成（工具装不上、渲染一直失败）就在回复里说清卡在哪、要用户做什么，不留半成品。

## 3. 回复

说做了什么（放了哪些文件、什么尺寸、用了什么工具），说一句「要改就在这里直接说」。提到的文件和这条内容都写成链接（地址见 ANNULO.md，文件用 `&file=<文件夹里的相对路径>`）。

## 4. 用户在这段对话里接着改

用户看完会回到这段对话里接着说，也可能在别的对话里引用这条内容（`@articles:<id>`）。

- 先 `annulo run folder.create` 一次（记下这段对话），再看文件夹现在的样子：用户可能在页面上改过、删过、加过文件。
- **改一处**（「第 2 段短一点」「封面字大一点」）：直接改那个文件，别的不动。
- **大改、重做**（「换一种风格再来一版」）：另存一份（`脚本 v2.md`、新的版本目录），旧的留着，回复里说新的在哪。
- 用户定下来的新要求、决定，记进 `稿子.md`，下次做的时候还用得上。
- 用户说的不是改这条内容（问问题、换个选题），照常回答。
