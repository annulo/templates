# 内容模型：每条内容一个文件夹

2026-10-15 定，**只用在自媒体工作台**（`creator/`）。产品运营、外贸照旧用 core 的内容中心（`core/components/views/Content.tsx`，稿子 + 正文 + 产物，见仓库根目录 `docs/artifacts.md`）。
这一版是照一个用户（作者自己）的用法做的，不代表所有人都该这么用：不同的模板可以有自己的内容中心。

## 为什么改

### 一篇里做了两支片子，发不出去

在「测试自媒体」里重做 Annulo 宣传片：一篇视频文章，稿子里写要求、参考旧版。和助手聊下来要做两支：A 外贸版、B 开源版。助手只好停下来问「拆成两篇，还是都记在这一篇里？」，因为一篇文章发出去的永远是同一份（一个标题、一段简介、一个「正在使用」的视频）。

### 没有 Annulo 时，同样的事一点都不别扭

用户原来的做法：Notion 写文档 → AI 优化 → 建一个 git 仓库 → AI 写脚本、用户反复改 → 生成视频；A、B 两版的视频和文案（md）都在仓库里 → 发布时打开平台，粘贴文案、传视频，发两次。

**干活的地方**（仓库）和**发出去的东西**（每次挑的视频 + 文案）是分开的。仓库里有几个版本都行，发几次、每次发哪份，到发的时候才决定。

老模型里「文章」同时是这两样，所以做出两个版本就要先决定拆不拆；同一件事发到不同形式的平台要拆成几篇（改写另存一篇）；产物里要标「正在使用」。

## 现在的模型

- **一条内容 = 一个文件夹**，在项目的工作目录里：`~/Annulo/<项目名>/内容/<名字>`（服务端部署是 `<数据目录>/work/<项目名>/内容/<名字>`）。文章表 `articles` 一行还是一条内容，`folder` 字段记文件夹相对工作目录的路径，表名、字段都不改。
- **稿子、脚本、文案、视频、参考都是里面的文件**，可以分目录（A 版、B 版各一个目录）。用户和 AI 读写的是同一份文件：用户在页面上改，AI 在对话里直接改目录。脚本不进资料库。
- **稿子**是最外层的 `稿子.md`（英文界面 `brief.md`）：这条内容要做什么、要求、大纲、参考。没有单独的稿子框。
- **文案**是名字带「文案」的 `.md`（英文 `copy.md`）：开头 `---` 包住 `title:`、`tags:`，下面是正文或视频简介。
- **长文**是 Markdown：图片放旁边目录、用相对路径（`![](图/1.png)`），视频写成单独一行的 `<video src width height controls></video>`。页面上用富文本编辑器直接读写 md（官方的 `@tiptap/markdown`，不经过 HTML；`components/rich/mdExtensions.ts` 加了表格、任务列表，改了转义和表格的写法，让读进来再存回去尽量不改原文），能切到源码。开头的 `---` 头不进编辑器，原样留着。
- **产物**就是文件夹里的文件，不再是资料库里带 `article_id` 的一条。资料库只放几条内容都会用到的素材。
- **内容没有类型**，**发布是挑选**：点「发布」挑这次发成什么（图文 / 视频 / 长文），文字从文件夹里挑一份 `.md`（标题、话题当场能改），图文挑一组图、视频挑一个视频（文件夹里的直接点选，也能从资料库选），再选账号。打开时按文件夹里有什么猜发成什么（有视频发视频，有图发图文，否则长文）；挑了文案，同一个目录里的图、视频自动配上（自己点过的不动）。每个账号新建一条帖子，**存什么发什么**：排期到点照帖子发，不再按文章重新生成。帖子里记的是文件夹里那个文件的引用（不复制一份），排期以后文件改过了、或者找不到了，到点不发，帖子标成失败写明原因，用户看过点「重发」发现在的版本。同一条内容可以发好几次（A、B 两支各发一次），没有「正在使用」。
- **发布记录**：每条显示这次发的是什么（第一张图或视频、标题），阅读、点赞、评论、收藏、分享一个个列出来，能马上「更新数据」（重新采集这个账号）。
- **交给 AI 只有一个入口**：顶上的「交给 AI」。文件夹那排不放「继续对话」「在对话里改」（和它重复）；要接着改，在右侧对话历史里回到那段对话，或者引用这条内容新开一段。在对话里跑 `folder.create` / `folder.write` 仍会把对话记到 `articles.chat_id`。
- 交给 AI「在这条上做」是自媒体自己的任务 `tasks/work-on-content.md`：做出来的都放进文件夹，不 `annulo upload`、不 `assets.add`。
- **新建内容**不选类型：弹窗里写的（第一行当名字）存成 `稿子.md`；从选题来的，选题的标题和简报也写进稿子、选题标成已做。「自己写」建好就打开；「让 AI 做」建好后交给 `work-on-content` 照稿子做（什么都没写也没选题，就让它从选题池挑一个）。`write-article` 任务自媒体不再用。

宣传片的例子：一条内容「Annulo 宣传片（重做）」，`稿子.md` 写要求；助手在同一段对话里做出 `A 外贸版/`、`B 开源版/` 两个目录，各有脚本、文案、成片；要发时点两次「发布」，一次挑 A 的视频和文案，一次挑 B 的。助手不用停下来问拆不拆。

## 页面

内容页从上到下：名字（双击改名，文件夹是按老名字建的就跟着改）→ 文件 → 发布记录。

**界面上只说「内容」，不说「文件夹」**（2026-10-25）：内容和文件夹是一回事，界面上两个名字会让用户以为是两层（内容「有」一个文件夹）。所以文件那块标题是「文件」，发布弹窗说「这条内容里的图」；「文件夹」只留在系统操作里（打开文件夹、在文件夹中显示、找不到文件夹）。界面上「文章」也都改叫「内容」（新建内容、做成内容、让 AI 做）。
不按文件名或目录区分「成品 / 过程」：图文、长文的文件很少，分了反而多一层；文件名约定要用户记，也和各人的习惯打架。视频的中间产物照旧放 `草稿/`（为了不同步大文件）。

- 文件夹默认**网格**：所有文件铺平（不分目录），稿子排第一，其余最近改的在前；图片、视频显示缩略图，名字下面写在哪个目录。可以切成**树**（左边目录树，右边看 / 改），选哪种记在这台电脑上。只有一个文件时直接打开它。
- 点开一个文件：文本在页面里改（md 默认富文本，「富文本 / 源码」切换和保存在一排），图片、视频预览；文件名双击改名；能用系统程序打开、在文件夹中显示、删除（进废纸篓）。
- AI 在对话里改文件不经过表、没有推送：页面看得见时每 4 秒重读一次。打开着的文件被别处改了：没改过就直接换成新的，改过了提示「载入新版本 / 接着改」。保存不会重新加载编辑器；「富文本 / 源码」和保存那排、编辑器工具条都吸在页面顶栏下面。
- 打开一条还没有文件夹的内容就建一个，老数据搬进去，只搬一次，表里的留着不动：稿子 → `稿子.md`，正文 → `文案.md`，配图 → `配图/`，视频 → `视频.mp4`，资料库里这篇的产物 → `产物/<名字>/`（只搬本机文件）。

## 实现

- **Annulo 原语**（能力版本 46，`internal/localfn/fs.go`、`internal/server/workfiles.go`）：本机函数的 `ctx.fs` 读写项目工作目录（`list / stat / read / write / mkdir / move / trash / copy / ref / resolve / toLocal / open`），`ctx.workspace.work_dir` 是这个目录；页面用 `/_annulo/work-files/<路径>` 显示里面的图片、视频。能力版本 62 起 `ctx.fs.ref(path)` 给文件的引用（`folder:<文件夹 id>/<路径>#<版本>`，文件夹改名、挪位置也找得到；不在产物文件夹里是 `work:<路径>#<版本>`），`b.upload` 直接认，`ctx.fs.resolve(ref)` 看现在在哪、还在不在、改过没有，页面用 `/_annulo/work-ref/<引用>` 显示。`creator/annulo.json` 的 `min_annulo_api` 是 46：老 Annulo 没有 `ref`，发布时照旧用 `toLocal` 复制成本机文件。
- **模板**：自媒体的内容中心是从 core 分出来的一份 `components/views/CreatorContent.tsx`（`pages/index.tsx` 用它），文件夹在 `components/Folder.tsx`，本机函数 `local/folder.ts`；编辑器的 md 扩展 `components/rich/mdExtensions.ts`；发布、搬老数据时的 md ↔ HTML 在 `lib/mdhtml.ts`（marked、turndown）。这些包都在 `talizen.config.ts` 的 importMap 里。
- 发布：`components/FolderPublish.tsx` 挑内容，`folder.publish` 把要发的文件夹里的文件记成引用（`ctx.fs.ref`，0.19.0 起；以前是 `toLocal` 复制成 `local:<name>`，发帖的视频因此在 `~/.annulo/files/` 里多一个名字，搬项目时还得认出是同一个文件），资料库的地址原样用，按插件的 `fromContent` 生成每个账号的帖子、过平台检查，页面放进发布队列。发布记录用 core 的 `PublishRecords`（`detailed`）。社媒插件 0.8.3 起排期到点照帖子发，0.8.23 起认引用、到点先查文件（`_source.ts` 的 `fileRefProblems`）。

## 产物文件夹（2026-10-22，Annulo 能力版本 59）

内容文件夹同时是 Annulo 的**产物文件夹**（Annulo 仓库 `docs/collab-local-agent.md`）：`folder.create` 调 `ctx.folders.create`，文章表多一个 `folder_id`。
- 挪了、改了名按 id 找回来（`folderOf`），改名走 `ctx.folders.move`；老 Annulo 没有 `ctx.folders`，只用 `folder` 路径，照旧能用（`min_annulo_api` 不用调）。
- 团队服务器上，用户电脑上的 Claude Code 拿 `folder.create` 返回的 `folder_id` 把文件夹拉下来做、做完推回去（`annulo fs pull / push`，只看一两个文件用 `annulo fs ls / get / put`，任务 `tasks/work-on-content.md` 写了）。
- **中间产物不同步**：建文件夹时写一份默认的 `.annuloignore`（`草稿/`、`drafts/`、`cache/`、`*.tmp`）。做视频时的草稿视频、草稿音频、试渲染的片段放进 `草稿/`，只留在做的人电脑上；成片、定稿的文案放外面。页面的网格不显示 `草稿/` 里的文件，树里还看得到。
