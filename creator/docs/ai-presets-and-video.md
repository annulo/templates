# AI 预设与视频制作

所有「交给 AI 做」的操作都按同一套逻辑：**交给助手，Prompt 是 xxx**。改写成图文、扩成长文、做成视频、给视频提意见都是这样，区别只在产出什么。实现在：`core/lib/presets.ts`、`core/components/Presets.tsx`、`core/components/RewriteDialog.tsx`（交给 AI 弹窗），`creator/components/VideoPanel.tsx`（视频版本），`creator/local/video.ts`，任务 `creator/tasks/make-video.md`、`revise-video.md`。core 只在调用方传了 `video`（`VideoMaking`）时做视频，别的模板不受影响。

## 预设

一条预设 = 名字 + 产出类型 + 用户写的 Prompt，作用在一篇文章上，用来开始一件**新任务**。执行一条预设就是开一段新对话，在后台跑，在右侧打开，按产出类型选任务、把 Prompt 当作这次的要求传进去。

| 产出类型 | 作用在 | 任务 | 结果 |
|---|---|---|---|
| `article` 长文、`post` 图文笔记 | 一篇文章 | `rewrite-article`（已有） | 另存一篇新文章，`source_id` 指回原文 |
| `video` 视频 | 一篇文章（当文档用） | `make-video` | 新建一篇视频文章（`source_id` 指回文档），做出第一版 |

- **Prompt 写「要什么样的」**：时长、比例、风格、节奏、语气、字数，想指定工具也写在这里。怎么存结果（字段格式、登记版本、文件存本机）是系统规则，写在任务文件里，用户看不到也改不到。
- **产出类型必须有**：页面要按它判断预设出现在哪里，任务要按它决定怎么存。不让助手从 Prompt 里猜。
- **默认预设来自模板**：写在 `core/lib/presets.ts`（名字、要求在 `core/messages` 的 `presets.builtin.<id>`），现在有「做成视频」，项目能做视频（传了 `videoTask`）时才出现。用户改了默认预设存一行 `builtin = <id>`，删了存一行 `builtin + hidden`，「恢复默认」删掉那行；用户自己加的直接存表。页面上合在一起显示。
- **入口**：文章页的「改写」弹窗改成「交给 AI」：先选预设（可以直接改这次的 Prompt），也能临时写一段，写好的能「存为预设」。

**接着改 AI 做出来的东西不用预设、不新开对话**：回到做它的那段对话直接说（Annulo AGENTS.md「接着改 AI 做出来的东西」）。新开对话只给不需要之前上下文的新任务。

不再有「剧本」这个概念：做视频的依据就是一篇文档，可以是内容中心里的一篇长文，也可以是从 Notion 导入的（`core/local/docsync.ts`）。要精确到秒的分镜，就直接写在文档里。改文档的方式和普通文章一样：自己改、AI 改，或者从 Notion 同步。

## 视频版本

表 `video_versions`，一行是一个版本：

| 字段 | 说明 |
|---|---|
| `article_id` | 属于哪篇视频文章 |
| `parent_id` | 从哪个版本改过来；第一版为空 |
| `prompt` | 这一版的要求：预设的 Prompt 或用户的意见原文 |
| `n`、`notes` | 第几版；助手对这一版的说明（怎么做的、改了什么，不写路径） |
| `doc_snapshot` | 制作这一版时文档的内容：文档以后会改，要说清楚这一版是照哪一稿做的。只在版本详情里展开看 |
| `chat_id` | 做这一版的对话（`video.start` 从 `ctx.chat_id` 记下） |
| `file` | 成片，`local:<name>`，存在本机、不上传 |
| `duration`、`width`、`height` | 时长（秒）、尺寸 |
| `status`、`error` | `making` / `done` / `failed`，失败原因 |
| `created_at` | |

- 每次渲染都算一个新版本，可以删。成片同时进资料库（`assets.kind = video`，`url` 是 `local:<name>`）。
- `articles.video` 指向当前选用的那一版的 `file`；版本列表里「设为当前」就是改它。发布还是现在的流程：选好一版，点「发布」，勾选 YouTube、抖音、B 站账号。
- 想要配套的图文，在文档或视频文章上用「改成图文笔记」这类预设，不放进主流程。
- **要改就回到做它的那段对话**：页面上「继续对话」打开当前版的对话（没记就用最近一个记了的），用户在对话里直接说，助手照 `make-video` 第 5 步每改一次开一个新版本。页面上不弹框收意见、不新开对话。对话找不到（老数据）时才给「在新对话里改」：新开一段，照 `revise-video` 先问要改什么。
- 页面：视频文章详情里，播放器下面是版本列表（每版能播放、看要求、看当时的文档、打开做它的对话、设为当前、删除）。

## 视频怎么做、工作文件放哪

模板不预设任何做视频的代码，也不带视频插件：用什么工具、什么框架（Remotion、ffmpeg、HyperFrames……）交给助手自己选，用户想指定就写在 Prompt 里（默认预设「做成视频」可以提一句）。任务文件只规定产出：

- 产出一个视频文件，登记成本机文件（`local:<name>`），按 `video_versions` 的字段记一个版本；
- 尺寸、时长照要发的平台的限制（和改写一样从上下文里拿）。

视频的源码是做视频的中间产物，**不放进项目目录**：项目目录里只有运营后台自己的代码（页面、本机函数、表、任务），它会进项目的 git、推到 creght、参与模板升级，视频工程放进去会跟着走一遍这些流程。

**Annulo 只管自己的素材目录**（本机文件 `~/.annulo/files/<项目 id>/`）：成片用 `annulo upload --local <路径>` 复制进来，表里只记 `local:<name>`。原来的文件在哪、源码在哪，Annulo 不记、不管：表里不出现素材目录以外的路径，也不提供别的目录。

源码放哪不是视频独有的问题：助手做图片、做网站、写脚本、跑数据，都会产生要留着下次接着用的工作文件。所以这条约定写进 **Annulo 给助手的系统提示**（见下面第 3 条），对所有工作都成立，`make-video` 任务不另外写：

- **不要放进项目目录**（助手的当前目录，`~/.annulo/backends/<项目 id>/`），也不要放进 `~/.annulo` 下的任何地方。项目目录会进 git、推到 creght、参与模板升级；`~/.annulo` 是 Annulo 自己的数据。
- **要留着的工作文件放 `~/Annulo/<项目名>/`**（Windows `%USERPROFILE%\Annulo\<项目名>\`），一件事一个子目录（`video/`、`site/`、`scripts/`……），能共用的工程就共用，下次照同一条约定找回来接着用。它在用户的主目录下，访达、资源管理器里看得到，用户自己能备份、删除、用 git 管；不放「文稿」「桌面」「下载」，macOS 访问它们要弹授权窗。
- **用完就扔的临时文件**（抽的帧、下载的中间文件、试跑的结果）放助手自己的临时目录（Claude Code 的 scratchpad，或系统临时目录）。要留着的不放那里：scratchpad 每段对话一个，改版是新开的对话，下一次找不到；`/tmp` 重启和几天不用就会被清；助手也可能是内置助手或 Codex，没有 scratchpad。

这只是约定：Annulo 不创建、不扫描、不记录 `~/Annulo`，表里不出现这里的路径。用户想管这些文件的版本、推到自己的 git 仓库，直接跟助手说。

## Annulo 这边（能力版本 42，已做）

1. **`annulo upload --local <文件…>`**：把文件复制进项目的本机文件（和页面 `POST local/files` 同一条路），打印 `local:<name>`，不记原来的路径。用到它的任务所在的模板，把 `min_annulo_api` 调到 42。本机函数暂时不需要（做视频的是助手），没加 `ctx.*`。
2. **本机文件超过 90 天、但业务表里还引用着的不清**：上传后在后台读一遍所有业务表（包括插件的），找 `local:<name>` 和预览地址；读表出错这次就不清。
3. **系统提示里加了工作文件放哪**（`internal/agent/agent.go` 的 `workFilesPrompt`）：不放项目目录和数据目录；要留的放 `~/Annulo/<项目名>/`（服务端部署放 `<数据目录>/work/<项目名>/`，容器里只有数据目录不会丢）；临时的放系统临时目录；成品用 `annulo upload` 存进项目。Annulo 不建、不扫、不记这个目录。

## 还没定

- 配音和音乐：第一版只做字幕和动效，还是接 TTS（复用「设置 → 模型」里的服务商）。
- 预设要不要支持「自由」产出类型（产出什么由 Prompt 决定，结果只放进资料库）。先只做长文、图文笔记、视频三种。
- 文档在内容中心里是一篇普通的长文草稿，可能被误发出去。先不处理；需要的话加一个「只作文档，不发布」的标记。
