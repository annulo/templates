# 落地页和文章封面

2026-11-02 定。外贸、产品运营两个模板一起用（网站运营模块），自媒体模板有表和函数、侧栏不放入口。

## 落地页

为一个目标单独做的网站页面：拿询盘、推一款产品、接住一个搜索词。**不是文章**：不进内容中心、不走发布脚本。

- **怎么做**：助手直接改网站代码（creght 站点拉代码、写页面、`creght push` 到预览；WordPress 经 `channels.wpRequest` 建草稿页面）。
  版式不受 CMS 集合限制，能用站点已有的表单、组件。没选「CMS 里的结构化页面」：每个网站都要先配集合和页面模板，版式也被字段卡住。
- **入口**：侧栏「网站」组里的「落地页」（`components/views/Landing.tsx`）。新建时选网站、写这页要做什么（必填），可选推哪些产品、主关键词、其他要求；
  先 `landing.create` 建一条记录，再开一段对话跑任务 `tasks/landing-page.md`。
- **流程**：写简报（Markdown，存进 `brief`）→ 做页面 → 推预览、存 `preview_url`（状态 `preview`）→ 用户在那段对话里提意见接着改 → 用户说上线才上线（`live`、`url`）。
  改和上线都回到做它的对话（「继续对话」），页面上不收意见；找不到原来的对话才「交给 AI 接着做」新开一段。
- **写法**：`prompts/landing-page.md`，用户在页面「AI 要求」里改（存到 `user/prompts/landing-page.md`）。
- **记录**：`landing_pages` 表、`local/landing.ts`（`create` / `context` / `save`）。第一次上线记一条 `site_changes`（kind `landing`），两周后对比前后数据；从关键词来的把那个词挂上。
- **产品运营的 SEO 页面**（增长机会 → `seo-page-implement`）做新页面时也登记成落地页，在这里能看到、接着改。
- **从别处做**：产品（外贸产品页每个产品、产品运营的产品和用户场景）、关键词（关键词详情）、选题（写作简报弹框底部）上都有「做落地页」（`LandingButton`）：
  在原地弹出同一个新建框，来源（`product_ids`、`keyword_id`、`topic_id`）和一句建议的目标预先填好，用户确认或改了再交给 AI；这个来源已经做过的落地页列在框里，可以回到那段对话改，免得重复做。
  产品运营的增长机会走原来的「实现页面」，做新页面时同样登记（`opportunity_id`）。
- **多语言网站**：一个页面文件、文案按语言分开，新建时选做哪几种语言，各语言地址自动算，见 `multilingual.md`「落地页」。

## 长文的封面

- 文章表加 `cover`（三个模板都加），长文编辑框里在正文上面（上传、从资料库选），空的发网站时用正文第一张图。图文的封面还是第一张配图，视频的是 `video_cover`（外贸这次补上）。
- 「交给 AI → 做封面」做出来的图，在产物上点「设为封面」；助手用 `assets.add` 的 `use: "cover"` 直接设。
- 发布：`publishTo`（`local/_publish.ts`）把本机的封面和正文图片一起传到网站，发布脚本拿到的 `a.cover` 已经是网站上的地址（没设封面就是正文第一张图）。
  老的发布脚本自己从正文取封面、不读 `a.cover`：文章设了封面却没用上时，发布记录上写 `warning`，按钮「让 AI 更新发布脚本」照 `setup-publish` 改脚本。
